= Ordering Canon Wave 4: Subscriber Layer Cleanup

== Scope

Wave 4 retires the duplicate subscriber implementations that were placed under `src/Service/Subscriber/Order` and keeps subscriber classes in Symfony subscriber/listener-oriented layers.

This is intentionally a narrow cleanup wave. It does not rewrite the whole repository and does not delete the repository root. The apply script only overlays touched files and backs up/removes the explicitly listed duplicate subscriber files and now-orphan subscriber service interfaces.

== Canonical decisions

* Runtime event subscribers/listeners belong under `src/EventSubscriber` or `src/Subscriber/Event/...`, not under `src/Service/Subscriber/...`.
* Duplicate service-interface abstractions for event subscribers are not required when no consumer type-hints them and when Symfony dispatching is attribute/subscriber based.
* Canonical `OrderWorkflowSubscriber` keeps the richer workflow pricing/audit listener logic from the service-layer duplicate.
* Canonical `OrderApiAuditSubscriber` is introduced under `src/EventSubscriber` because the source duplicate was a kernel terminate listener and had no collision-safe target.
* `OrderWorkflowGuardSubscriber` is fixed to check `OrderEntity`; the previous file imported `OrderEntity` but checked an undefined `Order` symbol.
